InkaNetopology - Scanner Réseau & Docker

Cartographie interactive physique, virtuelle (VM), conteneurs Docker et IoT avec journalisation en temps réel.

1. Présentation Générale

InkaNetopology est une application web conçue pour explorer et cartographier automatiquement l'infrastructure d'un réseau local (LAN). L'application s'exécute sous forme de conteneur Docker et met l'accent sur la lisibilité des topologies hybrides combinant équipements physiques, hyperviseurs de virtualisation (Proxmox, VMware), conteneurs microservices (Docker) et flotte d'objets connectés (IoT).

2. Fonctionnalités Clés

  • Scan et identification automatique : Détection dynamique du sous-réseau (ex: 192.168.1.0/24), balayage ARP, ping ICMP et sondage des ports ouverts (80, 443, 22, 8006, 5000, 1883, 554 RTSP).
  • Différenciation graphique réaliste : Représentations distinctes pour les machines physiques (serveurs rack, switches manageables, routeurs, NAS), les machines virtuelles (VM), les conteneurs Docker et les équipements IoT (caméras IP 4K, capteurs radar mmWave, sondes ESP32, prises wattmètres).
  • Gestion dynamique des dépendances : Rattachement dynamique des machines virtuelles et des conteneurs Docker à leurs hôtes physiques respectifs, avec possibilité de réassignation ou migration à chaud.
  • Personnalisation complète : Remplacement des visuels par des images réalistes (URL personnalisée ou préréglages haute-fidélité), ajout d'étiquettes libres (Tags) et de métadonnées techniques clé-valeur (CPU, RAM, consommation électrique, flux RTSP).
  • Journalisation temps réel (Streaming SSE) : Flux d'événements continus sans rafraîchissement via Server-Sent Events, filtrable par niveau (DISCOVERY, INFO, WARN, ALERT) et par catégorie (ARP, PORT, DOCKER, VM, IOT).
  • Mode sombre natif : Interface moderne, typographie soignée et chiffres tabulaires monospaces (JetBrains Mono).

3. Où se trouve l'image du conteneur ?

📦 Emplacement & Registre de l'image Docker

L'image du conteneur d'InkaNetopology peut être gérée selon deux modalités :

  • 1. Construction locale (sur votre machine hôte) :
    L'image est construite directement depuis le fichier Dockerfile présent à la racine du projet avec la commande : 
    docker build -t inkatypik/inkanetopology:latest .
    Dans ce cas, l'image est stockée localement dans le moteur Docker de votre système (sous /var/lib/docker/overlay2 sur Linux) et apparaît dans la commande docker images sous le nom inkatypik/inkanetopology:latest.
  • 2. Registre distant Docker Hub / GHCR (Déploiement direct) :
    L'image porte l'identifiant canonique : 
    inkatypik/inkanetopology:latest
    Pour la publier sur Docker Hub : 
    docker push inkatypik/inkanetopology:latest
    Pour la déployer sur un autre serveur sans cloner les sources : 
    docker pull inkatypik/inkanetopology:latest

4. Fichier Docker Compose (`docker-compose.yml`)

Voici le fichier docker-compose.yml complet requis pour le déploiement. Ce fichier est optimisé pour permettre au conteneur d'accéder directement au réseau physique local de la machine hôte.

docker-compose.yml 
services:
  inkanetopology:
    build:
      context: .
      dockerfile: Dockerfile
    image: inkatypik/inkanetopology:latest
    container_name: inkanetopology-scanner
    restart: unless-stopped

    # CRITIQUE : Le mode 'host' permet au conteneur de partager la pile réseau
    # de l'hôte afin d'émettre des requêtes ARP broadcast sur le réseau local physique
    # et de recevoir les annonces mDNS/SSDP des équipements IoT sans isolation NAT.
    network_mode: host

    # Capacités Linux nécessaires pour forger des raw sockets (ping ICMP / ARP)
    cap_add:
      - NET_ADMIN
      - NET_RAW

    environment:
      - NODE_ENV=production
      - PORT=3000

    volumes:
      # Montage en lecture seule de la table ARP et des interfaces réseau du noyau Linux
      - /proc/net:/proc/net:ro
      - /sys/class/net:/sys/class/net:ro
      # Montage en lecture seule du socket Docker pour l'inventaire dynamique des conteneurs
      - /var/run/docker.sock:/var/run/docker.sock:ro

Détail des directives critiques

Directive Rôle & Rationale
network_mode: host Indispensable pour un scanner réseau. En mode pont par défaut (bridge), Docker confine le conteneur dans un sous-réseau NAT virtuel (172.17.x.x) bloquant les broadcasts ARP vers votre LAN physique (192.168.1.x). Le mode host supprime cette barrière.
cap_add: [NET_ADMIN, NET_RAW] Donne au processus Node.js la capacité de créer des raw sockets ICMP et ARP sans devoir exécuter tout le conteneur avec le privilège --privileged global.
/proc/net:/proc/net:ro Permet à l'application de lire directement /proc/net/arp sur l'hôte Linux pour récupérer instantanément les correspondances IP/MAC connues du noyau.
/var/run/docker.sock:ro Permet d'interroger le moteur Docker de la machine hôte pour inventorier automatiquement les conteneurs actifs et les relier à l'hôte physique.

5. Procédure d'Installation

Méthode 1 : Déploiement avec Docker Compose (Recommandé)

  1. Créer le répertoire de travail : 
    mkdir -p /opt/inkanetopology && cd /opt/inkanetopology
  2. Créer le fichier docker-compose.yml : Collez le contenu ci-dessus dans ce fichier.
  3. Construire et démarrer l'application : 
    docker compose up -d --build
  4. Vérifier que le conteneur fonctionne : 
    docker compose ps
docker compose logs -f

Méthode 2 : Lancement en une ligne (Docker CLI)

Bash (Terminal) 
docker run -d \
  --name inkanetopology-scanner \
  --restart unless-stopped \
  --net=host \
  --cap-add=NET_ADMIN \
  --cap-add=NET_RAW \
  -v /proc/net:/proc/net:ro \
  -v /sys/class/net:/sys/class/net:ro \
  -v /var/run/docker.sock:/var/run/docker.sock:ro \
  -e PORT=3000 \
  -e NODE_ENV=production \
  inkatypik/inkanetopology:latest

6. Guide d'Utilisation Pas à Pas

6.1 Accéder à l'application

Dans votre navigateur, accédez à :
http://<IP_DE_VOTRE_SERVEUR>:3000 (par exemple http://192.168.1.10:3000).

6.2 Lancer un scan réseau

Dans la barre d'outils supérieure :

  • Sous-réseau : Vérifiez ou saisissez le CIDR à explorer (ex: 192.168.1.0/24).
  • Mode de scan :
    • Découverte Rapide (ARP/ICMP) : Détecte les équipements sous tension et récupère les adresses MAC.
    • Scan Approfondi (Ports & OS) : Vérifie les ports d'administration pour identifier l'OS et les services.
    • Audit Spécialisé IoT & Domotique : Détecte les flux RTSP des caméras, brokers MQTT et modules ESP32.
  • Cliquez sur « Scanner le réseau ». Une jauge temps réel indique la progression et chaque équipement découvert est ajouté au schéma.

7. Cartographie & Visualisation des Liens

L'onglet « Topologie Réseau » propose un espace infini interactif :

  • Navigation : Cliquez-glissez pour vous déplacer (pan), utilisez la molette de la souris ou les boutons + / - pour zoomer.
  • Repositionnement (Drag & Drop) : Cliquez sur n'importe quel nœud pour le déplacer. Sa position est automatiquement mémorisée.
  • Lignes continues bleues : Câbles physiques reliant les équipements au switch ou routeur avec libellé du port et du débit (ex: Port 4 (1Gbps), PoE 7.5W).
  • Lignes pointillées avec flèches : Liens de virtualisation reliant chaque VM (violet) et conteneur Docker (cyan) à sa machine physique hôte.

8. Gestion des Dépendances & Hôtes Physiques

L'onglet « Hôtes & Dépendances » regroupe vos serveurs physiques (Serveur Proxmox, hôte Docker HP, NAS Synology) :

  • Chaque hôte liste ses Machines Virtuelles et ses Conteneurs Docker.
  • Migration / Réassignation dynamique : Sur chaque VM ou conteneur, un menu déroulant permet de changer d'hôte parent ou de détacher l'équipement en un clic.
  • Création rapide : Utilisez les boutons « Ajouter VM » ou « Ajouter Conteneur » pour provisionner un nouvel équipement directement rattaché à cet hôte.

9. Personnalisation des Images & Métadonnées

Cliquez sur l'icône Crayon (Éditer) sur un équipement pour ouvrir l'inspecteur :

  • Image réaliste : Renseignez une URL d'image personnalisée ou sélectionnez l'un des préréglages visuels (serveur rack Dell, routeur UniFi, switch 24P, NAS Synology, caméra IP 4K, capteur mmWave, etc.).
  • Étiquettes (Tags) : Ajoutez des étiquettes (ex: Production, DMZ, VLAN 20, Critique).
  • Métadonnées clé/valeur : Définissez des spécifications techniques précises (CPU, RAM, consommation électrique, flux RTSP, version firmware).
  • Test Ping : Cliquez sur « Tester Ping » pour mesurer la latence en millisecondes et vérifier les ports ouverts.

10. Intégration Reverse Proxy HTTPS (Nginx)

Pour exposer InkaNetopology avec un domaine et un certificat SSL/TLS via Nginx :

/etc/nginx/sites-available/inkanetopology.conf 
server {
    listen 80;
    server_name topology.mondomaine.local;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name topology.mondomaine.local;

    ssl_certificate /etc/letsencrypt/live/topology.mondomaine.local/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/topology.mondomaine.local/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;

        # OBLIGATOIRE : Configuration pour le streaming temps réel (Server-Sent Events)
        proxy_set_header Connection '';
        proxy_set_header Host $host;
        proxy_buffering off;
        proxy_cache off;
        chunked_transfer_encoding off;
        proxy_read_timeout 86400s;

        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
⚠️ Directive essentielle pour le streaming SSE

La directive proxy_buffering off; est obligatoire pour éviter que le proxy Nginx ne stocke les paquets du journal en mémoire tampon au lieu de les transmettre instantanément au navigateur.

11. Dépannage & FAQ

Q1. Pourquoi aucun équipement n'est découvert lors d'un scan ?

Le conteneur a très probablement été démarré sans network_mode: host. Sans ce mode, les paquets ARP ne peuvent pas sortir du réseau virtuel NAT de Docker. Vérifiez également que le sous-réseau indiqué dans la barre d'outils correspond à votre adressage réseau.

Q2. Comment changer le port 3000 ?

En mode host, modifiez la variable d'environnement PORT dans votre docker-compose.yml (par exemple PORT=8080).

Q3. Comment exporter ou sauvegarder la topologie ?

Cliquez sur le bouton de téléchargement (Export) dans la barre d'outils supérieure pour télécharger un fichier inkanetopology-export.json contenant la totalité des équipements, positions et métadonnées.
