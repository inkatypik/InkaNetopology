1. Présentation Générale

InkaNetopology est une solution logicielle tout-en-un conteneurisée sous Docker qui permet d'explorer, de cartographier et de superviser graphiquement un réseau local (LAN). L'application modélise avec une grande clarté les topologies complexes et hybrides : machines physiques, hyperviseurs de virtualisation (Proxmox, VMware ESXi, KVM), conteneurs microservices (Docker) et parcs d'objets connectés (IoT).

Au démarrage, l'application propose un inventaire initial vide pour vous laisser cartographier fidèlement votre réseau sans données factices imposées. Un bouton de réinitialisation permet de charger à tout moment une topologie de démonstration pour les tests.

3. Fichier Docker Compose (`docker-compose.yml`)

docker-compose.yml 
services:
  inkanetopology:
    image: ghcr.io/inkatypik/inkanetopology:latest
    build:
      context: .
      dockerfile: Dockerfile
    container_name: inkanetopology-scanner
    restart: unless-stopped

    # CRITIQUE : Le mode 'host' permet au conteneur de partager la pile réseau
    # de l'hôte afin d'émettre des requêtes ARP broadcast sur le réseau local physique.
    network_mode: host

    # Capacités Linux nécessaires pour forger des raw sockets (ping ICMP / ARP)
    cap_add:
      - NET_ADMIN
      - NET_RAW

    environment:
      - NODE_ENV=production
      - PORT=3000

    volumes:
      # Persistance de la topologie, des zones, types et rôles
      - /chemin/vers/votre/dossier/data:/app/data
      # Montage optionnel du socket Docker pour l'inventaire dynamique
      - /var/run/docker.sock:/var/run/docker.sock:ro

Fichiers de persistance dans /app/data

Fichier Contenu & Description
data/devices.json Liste de tous les équipements réseau, liaisons, adresses IP/MAC, coordonnées spatiales et appartenance aux zones.
data/zones.json Définition des zones géographiques (pièces, baies de brassage, sous-répartiteurs, sites) avec leurs couleurs et dimensions.
data/device-types.json Catalogue dynamique des types d'équipements configurés avec leurs styles visuels.
data/device-subtypes.json Catalogue des sous-types et rôles métier, incluant les rôles restreints à un équipement particulier.
data/network-logs.json Historique persistant des événements réseau et alertes.

5. Topologie en Étoile & Cœur de Réseau (Centre de l'Étoile)

InkaNetopology intègre un moteur de disposition automatique en étoile :

  • Cœur de Réseau au Centre : Un ou plusieurs équipements peuvent être désignés manuellement comme cœur de réseau via l'option « Cœur de réseau (Centre de l'étoile) » dans leur fiche d'édition.
  • Bouton « Topologie en étoile » : Situé dans la barre d'outils, il réorganise instantanément tous les nœuds de manière harmonieuse autour du cœur central.
  • Rayons et Liaisons : Les liens de communication rayonnent avec fluidité depuis le switch/routeur central vers les équipements périphériques et les zones.
  • Légende Déplaçable & Réductible : La légende explicative de la topologie peut être déplacée à la souris et compactée pour libérer l'espace visuel.

6. Zones Géographiques Éditables & Déplaçables

Organisez spatialement votre réseau selon la réalité de vos locaux :

  • Types de zones : Pièces (Bureau, Salon, Cave), Sous-répartiteurs, Baies de brassage informatiques, Sites distants, ou zones libres.
  • Déplacement en bloc : Glissez l'en-tête d'une zone géographique pour déplacer tous ses équipements simultanément.
  • Renommage direct : Cliquez sur le nom de n'importe quelle zone directement sur le schéma pour la renommer en un clin d'œil.
  • Replier / Déplier : Chaque zone dispose d'un bouton pour masquer/déplier son contenu et éviter la surcharge visuelle.
  • Affectation immédiate : Lorsqu'un équipement change de zone géographique dans sa fiche, il est immédiatement repositionné à l'intérieur de sa nouvelle zone sur la topologie.

7. Groupes Hôtes & Machines (VMs et Docker)

Pour les environnements de virtualisation Proxmox, VMware ou Docker :

  • Clusters visuels : Un enclos pointillé regroupe automatiquement l'hôte physique et toutes ses machines virtuelles ou conteneurs.
  • Déplacement du groupe : Déplacez l'ensemble en glissant l'en-tête du groupe hôte.
  • Pliage / Dépliage : Réduisez les conteneurs ou VMs d'un hôte pour compacter le schéma, ou utilisez le bouton global « Tout replier » / « Tout déplier » dans la barre d'outils.
  • Anti-chevauchement strict : Le moteur de rendu garantit qu'aucun équipement ne se superpose ou ne déborde de sa zone ou de son groupe hôte.
  • Association corrigée : Les conteneurs découverts sont associés avec exactitude à leur véritable machine hôte d'exécution.

8. Gestion des Types d'Équipements & Rôles Métier

Accédez à la modale de gestion complète via le bouton « Types & Rôles » dans la barre d'outils :

Gestion des Types

Créez, modifiez ou supprimez des types d'équipements personnalisés. Attribuez-leur une couleur d'accentuation, une icône et une description. Les onglets de filtrage s'adaptent dynamiquement.

Gestion des Sous-Types & Rôles Métier

Gérez les rôles fonctionnels (Passerelle, Contrôleur AD, Reverse Proxy, SGBD, etc.). Un rôle peut être généraliste ou être lié spécifiquement à un équipement donné. Un badge de rôle s'affiche élégamment sur la fiche topologique du nœud.

9. Icônes Génériques & Import d'Image Locale

Fini les icônes imposées :

  • Icônes génériques modernes : Sélection soignée d'icônes vectorielles claires adaptées à chaque catégorie de matériel.
  • Import depuis la machine locale : Dans la fiche d'édition, le bouton « Choisir un fichier local » vous permet de sélectionner directement une image, un logo ou une photo sur votre ordinateur pour l'appliquer à l'équipement (sans hébergement externe requis).
  • Édition au clic direct : Cliquez simplement sur le nom d'un équipement dans le schéma pour ouvrir immédiatement sa fiche de configuration.

11. Test de Présence Régulier (Keepalive) & Rétention d'Inventaire

InkaNetopology intègre un système automatisé de surveillance active et de nettoyage de l'inventaire matériel, entièrement configurable depuis la modale des Paramètres :

Module Description & Fonctionnement
Test de Présence Régulier (Keepalive) Exécute en arrière-plan des tests ICMP (ping) et des sondages de ports TCP sur chaque équipement inventorié.
Fréquence réglable : 1 min, 2 min, 5 min (recommandé), 10 min, 15 min, 30 min ou 60 min.
Met à jour en temps réel le statut (En ligne / Hors ligne), la latence RTT en millisecondes et la date de dernière activité (lastSeen).
Nettoyage Automatique d'Inventaire (Auto-Prune) Supprime automatiquement de l'inventaire et de la topologie le matériel qui n'a pas été vu actif depuis plus d'une durée paramétrable.
Durées au choix : 1h (test rapide), 6h, 12h, 24h (1 jour), 48h, 72h, 1 semaine, 2 semaines ou 1 mois.
Protection du Cœur de réseau : Empêche la suppression des commutateurs et routeurs vitaux même en cas d'inactivité temporaire.
Actions Manuelles Immédiates Boutons dédiés pour déclencher un test de présence global instantané (« Tester maintenant ») ou purger immédiatement les équipements inactifs dépassant le seuil (« Purger maintenant »).

12. Intégration Reverse Proxy HTTPS (Nginx)

/etc/nginx/sites-available/inkanetopology.conf 
server {
    listen 80;
    server_name topology.mondomaine.local;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name topology.mondomaine.local;

    ssl_certificate /etc/letsencrypt/live/topology.mondomaine.local/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/topology.mondomaine.local/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;

        # OBLIGATOIRE : Configuration pour le streaming temps réel (Server-Sent Events)
        proxy_set_header Connection '';
        proxy_set_header Host $host;
        proxy_buffering off;
        proxy_cache off;
        chunked_transfer_encoding off;
        proxy_read_timeout 86400s;

        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

13. Dépannage & FAQ

Q1. Pourquoi aucun équipement n'est découvert lors d'un scan ?

Assurez-vous que le conteneur est lancé en network_mode: host. Sans ce paramètre, les requêtes ARP broadcast ne peuvent pas interroger votre réseau local physique.

Q2. Comment mettre à jour vers la dernière version ?

Exécutez simplement docker compose pull && docker compose up -d dans le répertoire du projet.

Q3. Pourquoi l'inventaire est vide au premier lancement ?

L'application a été conçue pour démarrer proprement sans équipements fictifs imposés. Vous pouvez immédiatement lancer un scan ou charger une topologie de démo via l'icône de réinitialisation.
