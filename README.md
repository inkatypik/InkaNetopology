**InkaNetopology** est une application web conteneurisée sous Docker conçue pour scanner le réseau local (LAN), identifier automatiquement les équipements connectés, modéliser avec précision leurs relations physiques et de virtualisation (machines physiques, machines virtuelles, conteneurs Docker, objets connectés IoT), et fournir une cartographie interactive en étoile avec zones géographiques et journalisation en temps réel.

- **Dépôt GitHub** : [https://github.com/inkatypik/InkaNetopology](https://github.com/inkatypik/InkaNetopology)
- **Image officielle (GHCR)** : `ghcr.io/inkatypik/inkanetopology:latest`

> **Note de conception & genèse du projet** : L'ensemble du projet InkaNetopology a été créé via **Google AI Studio** et tout le code produit (frontend React/Tailwind, backend Express/Node.js, moteur d'analyse réseau, calculs de disposition géométrique, API REST et Dockerfile) est **intégralement généré par intelligence artificielle**.

## 1. Démarrage Express en 1 Minute (via GitHub & GHCR)

Vous n'avez pas besoin d'installer Node.js ou de compiler le projet sur votre serveur :

```bash
mkdir -p /opt/inkanetopology && cd /opt/inkanetopology
curl -sSL https://raw.githubusercontent.com/inkatypik/InkaNetopology/main/docker-compose.yml -o docker-compose.yml
docker compose pull
docker compose up -d
```

Ouvrez ensuite votre navigateur sur `http://<IP-DU-SERVEUR>:3000`.

## 2. Fonctionnalités Clés Complètes

- **Détection Automatique & Scan Multi-Modes** :
  - Découverte automatique des sous-réseaux locaux (ex: `192.168.1.0/24`, `10.0.0.0/24`).
  - Balayage ARP broadcast, requêtes ICMP et sondage des ports de services (HTTP, HTTPS, SSH, Proxmox VE 8006, RTSP 554, MQTT 1883, etc.).
  - 3 modes de scan : *Découverte Rapide*, *Scan Approfondi (Services & Ports)*, *Audit Spécialisé IoT & Domotique*.
  - Reconnaissance automatique des fabricants matériels via les préfixes OUI (Ubiquiti, Dell, Synology, Raspberry Pi, Hikvision, Espressif, Philips Hue, Shelly, etc.).
  - Association précise des conteneurs à leur véritable machine hôte d'exécution.
- **Topologie Réseau en Étoile (Star Topology)** :
  - Organisation automatique en étoile avec le(s) équipement(s) cœur de réseau placé(s) majestueusement au centre.
  - Définition manuelle du statut cœur de réseau (`isCore`) sur un ou plusieurs équipements clés (routeur principal, switch de distribution, firewall).
  - Rayons de liaison visuels fluides rayonnant du cœur vers les équipements de distribution et d'extrémité.
- **Zones Géographiques Déplaçables & Repliables** :
  - Découpage visuel de l'infrastructure par zones réelles : *Pièces*, *Baies de brassage*, *Sous-répartiteurs*, *Sites distants*, etc.
  - Les zones sont déplaçables à la souris en bloc avec calcul automatique de l'enclos sans chevauchement.
  - Renommage direct en ligne du nom de la zone en cliquant sur son libellé.
  - Repliement / dépliement individuel de chaque zone pour aérer l'espace visuel.
  - Déplacement automatique et immédiat d'un équipement dans sa nouvelle zone lors de l'édition.
- **Groupes Hôtes & Machines Virtuelles / Conteneurs** :
  - Délimitation visuelle sous forme de cluster reliant les conteneurs Docker et les VMs à leur hôte parent physique.
  - Déplacement d'un groupe complet à la souris via son en-tête.
  - Dépliement / repliement individuel ou global ("Tout replier" / "Tout déplier") des groupes machines.
  - Algorithme anti-chevauchement strict garantissant l'intégrité de la vue sans superposition.
- **Gestion Dynamique des Types d'Équipements** :
  - Interface dédiée permettant d'ajouter, modifier et supprimer des types d'équipements personnalisés.
  - Attribution de couleur d'accentuation personnalisée, d'icône générique et de description.
  - Onglets de filtrage de la barre d'outils actualisés en temps réel selon les types configurés.
- **Gestion des Sous-Types et Rôles Métier** :
  - Catalogue riche de sous-types et rôles métier (Passerelle, Contrôleur AD, Reverse Proxy, SGBD, Supervision, etc.).
  - Rôles filtrables par type parent ou rattachés spécifiquement à un équipement donné (`deviceId`).
  - Ajout rapide de rôle à la volée depuis la fiche d'édition avec affichage du badge de rôle sur le nœud.
- **Édition Directe depuis la Topologie** :
  - Clic direct sur le nom de l'équipement dans le nœud topologique pour ouvrir immédiatement la fiche d'édition.
  - Bouton d'action épuré et modale de liaisons rapides (`QuickLinkModal`) sur le canevas.
- **Icônes Génériques Modernes & Import d'Image Locale** :
  - Large sélection d'icônes génériques vectorielles adaptées à chaque catégorie d'équipement.
  - Possibilité de charger une icône ou image personnalisée depuis son ordinateur local via l'explorateur de fichiers.
- **Imports & Exports Multi-Formats Haute Qualité** :
  - **Export & Import JSON** : sauvegarde et restauration intégrale de la topologie (équipements, zones, types, sous-types).
  - **Export PNG** : capture d'image haute fidélité sans limite de dimension canvas.
  - **Export PDF** : génération d'un rapport topologique au format A4 paysage.
- **Légende Interactive Déplaçable** :
  - Légende de la topologie repositionnable à la souris et réductible pour maximiser l'espace d'affichage.
- **Inventaire Vierge par Défaut** :
  - L'application démarre désormais avec un inventaire vide (aucun faux équipement imposé) ; possibilité de recharger une topologie de démonstration en un clic si nécessaire.
- **Journalisation en Temps Réel** :
  - Flux d'événements continus via Server-Sent Events (SSE) avec filtrage par criticité et catégorie.

## 3. Architecture Technique & Persistance des Données

- **Frontend** : React 19, TypeScript, Tailwind CSS, Lucide Icons, Canvas SVG dynamique, `html-to-image`, `jspdf`.
- **Backend** : Node.js, Express, Server-Sent Events (SSE), commandes réseau sécurisées (`arp`, `ping`, inspection ports TCP).
- **Persistance des données** (dossier `/app/data` monté en volume) :
  - `data/devices.json` : base des équipements réseau et liaisons.
  - `data/zones.json` : zones géographiques (pièces, baies, sites).
  - `data/device-types.json` : types d'équipements dynamiques et couleurs.
  - `data/device-subtypes.json` : sous-types et rôles métier personnalisés.
  - `data/network-logs.json` : historique des événements réseau.
- **Image Docker (GHCR)** :
  - `ghcr.io/inkatypik/inkanetopology:latest`
  - Multi-architecture : `linux/amd64` (serveurs x86) et `linux/arm64` (Raspberry Pi 4/5, NAS ARM).

## 4. Fichier Docker Compose

Voici le fichier `docker-compose.yml` complet et optimisé :

```yaml
services:
  inkanetopology:
    # Image officielle pré-construite hébergée sur GitHub Container Registry (GHCR)
    image: ghcr.io/inkatypik/inkanetopology:latest
    # Build local optionnel lors d'une compilation depuis les sources
    build:
      context: .
      dockerfile: Dockerfile
    container_name: inkanetopology-scanner
    restart: unless-stopped

    # CRITIQUE: Le mode 'host' permet au conteneur de partager directement
    # les interfaces réseau physiques de la machine hôte pour émettre
    # des requêtes ARP broadcast sur le LAN et écouter les paquets mDNS/SSDP.
    network_mode: host

    # Capacités Linux nécessaires pour forger des raw sockets (ping ICMP / ARP)
    cap_add:
      - NET_ADMIN
      - NET_RAW

    environment:
      - NODE_ENV=production
      - PORT=3000

    volumes:
      # CRITIQUE : Définissez ici votre chemin de stockage local (machine hôte)
      # selon votre environnement (ex: OpenMediaVault, Synology, Debian, Ubuntu).
      # Remplacez /chemin/vers/votre/dossier/data par votre chemin de stockage réel :
      #   Ex. OpenMediaVault : /srv/dev-disk-by-uuid-.../DOCKER/inkanetopology/data:/app/data
      #   Ex. Linux standard : /opt/inkanetopology/data:/app/data
      #   Ex. Synology NAS   : /volume1/docker/inkanetopology/data:/app/data
      - /chemin/vers/votre/dossier/data:/app/data
      # Montage optionnel du socket Docker pour l'inventaire dynamique des conteneurs
      - /var/run/docker.sock:/var/run/docker.sock:ro
```


### Méthode 3 : Lancement direct en ligne de commande (Docker CLI)

```bash
docker run -d \
  --name inkanetopology-scanner \
  --restart unless-stopped \
  --net=host \
  --cap-add=NET_ADMIN \
  --cap-add=NET_RAW \
  -v /opt/inkanetopology/data:/app/data \
  -v /var/run/docker.sock:/var/run/docker.sock:ro \
  -e PORT=3000 \
  -e NODE_ENV=production \
  ghcr.io/inkatypik/inkanetopology:latest
```

## 6. Guide d'Utilisation Détaillé

### 6.1 Accès à l'interface & Inventaire initial

Accédez à `http://<IP_DU_SERVEUR>:3000`.  
Par défaut, l'inventaire est vierge afin de vous laisser bâtir votre propre cartographie. Vous pouvez immédiatement lancer un scan réseau ou ajouter un premier équipement via le bouton **« + Ajouter »**. Si vous désirez explorer une maquette complète, le bouton de réinitialisation vous permet de charger une topologie de démonstration.

### 6.2 Lancer un scan réseau

1. Dans la barre d'outils, vérifiez ou personnalisez le champ **Sous-réseau** (ex: `192.168.1.0/24`).
2. Sélectionnez le mode de scan :
   - **Découverte Rapide** : balayage ARP/ICMP des hôtes actifs.
   - **Scan Approfondi** : identification de l'OS et des ports d'administration.
   - **Audit IoT** : détection des flux RTSP, brokers MQTT, modules domotiques.
3. Cliquez sur **« Scanner le réseau »**. La progression s'affiche en temps réel et les nouveaux équipements s'intègrent instantanément au graphe.

### 6.3 Vue Topologie Réseau (Schéma en étoile & Cœur de réseau)

L'onglet **« Topologie Réseau »** organise vos équipements sous forme d'étoile :
- **Topologie en étoile** : Cliquez sur le bouton **« Topologie en étoile »** dans la barre d'outils pour réagencer automatiquement le schéma avec le cœur de réseau au centre et les nœuds organisés en couronnes harmonieuses.
- **Définition du Cœur de Réseau** : Dans la fiche d'édition de n'importe quel équipement, activez la case **« Cœur de réseau (Centre de l'étoile) »**. L'équipement recevra un badge doré distinctif et servira de centre névralgique au schéma.
- **Navigation** : Déplacez-vous sur le canevas infini (clic-glissé) et ajustez le zoom avec la molette ou les boutons `+` / `-`.
- **Légende interactive & catégorisée** : La boîte de légende est déplaçable par glisser-déposer et réductible. Elle intègre 4 onglets dynamiques :
  - **Général** : identification visuelle du cœur de réseau (étoile dorée), câbles LAN physiques, liaisons virtuelles VM et liaisons Docker.
  - **Zones** : liste complète de vos pièces, baies, sous-répartiteurs et sites avec leurs pastilles colorées, badges de type, compteurs d'équipements et bouton de repliage direct.
  - **Types** : récapitulatif des types d'équipements (physiques, VM, Docker, IoT et types personnalisés) avec indicateur de couleur et décompte.
  - **Rôles** : inventaire de tous les rôles et sous-types attribués aux équipements (ex. passerelle WAN, hyperviseur, serveur web) et équipement rattaché.

### 6.4 Zones Géographiques (Pièces, Baies, Sous-Répartiteurs, Sites)

- **Gestion des zones** : Cliquez sur le bouton **« Gérer les zones »** pour créer vos pièces (ex: *Bureau*, *Salon*, *Garage*), baies (ex: *Baie Serveurs 42U*) ou sous-répartiteurs.
- **Enclos visuels dynamiques** : Les équipements d'une même zone sont entourés d'un contour discret avec leur nom et couleur.
- **Déplacement en bloc** : Glissez l'en-tête d'une zone pour déplacer l'ensemble de ses équipements d'un seul geste.
- **Renommage en un clic** : Cliquez directement sur le titre d'une zone pour la renommer sur-le-champ.
- **Replier / Déplier une zone** : Cliquez sur le bouton de réduction d'une zone pour compacter ses équipements lorsqu'ils ne nécessitent pas d'inspection détaillée.

### 6.5 Groupes Hôtes & Machines (VMs et Docker)

- Les machines virtuelles et conteneurs Docker associés à un serveur physique sont entourés d'un cluster dédié.
- Vous pouvez déplacer l'hôte et toutes ses machines d'un seul geste en glissant l'en-tête du groupe.
- Chaque groupe dispose d'un bouton pour replier les machines rattachées et épurer le graphe.
- Le bouton **« Tout replier / Tout déplier »** dans la barre d'outils permet d'agir sur l'ensemble de l'infrastructure instantanément.

### 6.6 Gestion Personnalisée des Types d'Équipements

Cliquez sur le bouton **« Types & Rôles »** dans la barre d'outils :
- **Onglet "Types d'Équipements"** : visualisez les types existants (*Physique*, *VM*, *Docker*, *IoT*) et ajoutez vos propres types (ex: *Pare-feu*, *Stockage SAN*, *Borne Wi-Fi*).
- **Attributs configurables** : libellé, couleur thématique, icône Lucide et description.
- Les types créés apparaissent directement dans les onglets de filtrage et dans les formulaires d'édition.

### 6.7 Gestion des Sous-Types & Rôles Métier

Dans la modale **« Types & Rôles »** :
- **Onglet "Sous-Types & Rôles Métier"** : définissez des rôles précis (ex: *Contrôleur de Domaine AD*, *Passerelle VPN WireGuard*, *Sonde Télémétrique*).
- **Association souple** : liez un rôle à un type parent ou réservez-le à un équipement spécifique via le champ `deviceId`.
- **Création inline** : lors de l'édition d'une fiche équipement, saisissez directement un rôle dans le champ dédié pour l'associer instantanément.

### 6.8 Édition Rapide, Icônes Génériques & Import Local

- **Édition directe au clic** : Cliquez directement sur le libellé d'un équipement dans le schéma pour ouvrir sa fiche.
- **Bouton de liaison rapide** : Sur chaque nœud, l'icône de liaison permet d'ajuster rapidement son switch de rattachement, son hôte physique ou sa zone géographique.
- **Icônes génériques** : Sélectionnez des icônes vectorielles claires adaptées à chaque matériel.
- **Import local d'icônes** : Cliquez sur **« Choisir un fichier local »** dans l'éditeur pour importer une photo ou un logo depuis votre poste de travail.

### 6.9 Vue Hôtes & Dépendances de Virtualisation

L'onglet **« Hôtes & Dépendances »** présente vos serveurs physiques sous forme de cartes d'infrastructure avec liste de leurs VMs et conteneurs, indicateurs de ressources et transfert à chaud vers un autre hôte.

### 6.10 Inventaire Tabulaire & Recherche Dynamique

L'onglet **« Inventaire Équipements »** fournit une table complète et filtrable avec recherche en direct sur IP, nom, fabricant, tags, VLAN et statut en ligne/hors ligne.

### 6.11 Journalisation en temps réel (SSE)

L'onglet **« Journal Temps Réel »** affiche la console des événements réseau diffusée par Server-Sent Events, avec options de pause de défilement, filtrage par niveau et copie rapide.

### 6.12 Export & Import (JSON, PNG, PDF)

Dans la barre d'outils :
- **Importer JSON** : restaure l'inventaire complet, les zones, types et dispositions depuis un fichier JSON précédemment exporté.
- **JSON** : télécharge le fichier complet `inkanetopology-export.json`.
- **PNG** : génère une capture haute résolution du schéma topologique sans les boutons d'interface.
- **PDF** : crée un document PDF vectoriel de la cartographie au format A4 paysage.

## 7. Intégration Reverse Proxy (HTTPS & Nginx)

Pour exposer InkaNetopology derrière **Nginx** ou **Nginx Proxy Manager** :

```nginx
server {
    listen 80;
    server_name topology.mondomaine.local;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name topology.mondomaine.local;

    ssl_certificate /etc/letsencrypt/live/topology.mondomaine.local/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/topology.mondomaine.local/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;

        # OBLIGATOIRE : Configuration pour le streaming temps réel (Server-Sent Events)
        proxy_set_header Connection '';
        proxy_set_header Host $host;
        proxy_buffering off;
        proxy_cache off;
        chunked_transfer_encoding off;
        proxy_read_timeout 86400s;

        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 8. Dépannage & FAQ

### Q1. Pourquoi aucun équipement n'est découvert lors d'un scan ?
Vérifiez que le conteneur s'exécute bien en `network_mode: host` (indispensable pour que les paquets ARP broadcast circulent sur votre réseau physique) et que le CIDR du sous-réseau correspond à votre plan d'adressage (ex: `192.168.1.0/24`).

### Q2. Comment mettre à jour vers la dernière version ?
```bash
docker compose pull
docker compose up -d
```

### Q3. Où sont conservées mes données (équipements, zones, types personnalisés) ?
Toutes les données sont stockées au format JSON dans le dossier `/app/data` du conteneur. Le montage de volume `- /chemin/vers/votre/dossier/data:/app/data` dans votre `docker-compose.yml` garantit la persistance définitive même en cas de mise à jour du conteneur.
